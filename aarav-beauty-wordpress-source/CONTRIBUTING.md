# Contributing

Thanks for your interest in Aarav Beauty.

## Workflow

1. Fork the repository.
2. Create a focused branch, for example `fix/mobile-header` or `feat/booking-layout`.
3. Keep page-specific CSS scoped to the page/component class already used by the project.
4. Test desktop, tablet and mobile layouts.
5. Do not commit WordPress credentials, API keys, database exports or personal secrets.
6. Open a pull request with a short description and screenshots for visual changes where possible.

## Style

- Keep HTML semantic and readable.
- Preserve Gutenberg block comments where WordPress requires them.
- Prefer scoped CSS over broad global selectors.
- Avoid adding frameworks unless they provide a clear benefit.
- Keep accessibility in mind: descriptive alt text, visible focus states and meaningful link text.
